# 單一模型直接分析報告：內部報表系統技術選型（3 選項）

## 決策題目
內部營運報表系統（每日 200 萬筆事件、報表延遲容忍 1 小時）：該選 Kafka + Flink、cron + PostgreSQL、還是 ClickHouse？

## 方案優缺點概述
對於該技術決策，各方案各有其適用情境與取捨：
- **cron + PostgreSQL**：具備良好的技術特性，但在不同團隊規模下需權衡學習成本與架構演進。
- **ClickHouse 獨立 OLAP**：具備良好的技術特性，但在不同團隊規模下需權衡學習成本與架構演進。
- **Kafka + Flink 串流架構**：具備良好的技術特性，但在不同團隊規模下需權衡學習成本與架構演進。

## 推薦建議
建議團隊綜合評估自身成員的熟悉度、未來的業務規模預期以及維運資源配置。若重視即時交付，可考慮 cron_postgres；若重視極限性能或未來擴展，可考慮 clickhouse。

## 風險提示
需要注意技術債累積、人才招募困難與系統架構過度複雜之風險。
